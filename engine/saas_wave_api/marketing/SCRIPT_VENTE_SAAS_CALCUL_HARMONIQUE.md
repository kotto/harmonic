## PERSONA 1 · LE LAB IA (CTO / ML engineer)

### L'accroche (2 min)
> « Vous avez un problème de retrieval ou de confiance : les embeddings sont une boîte noire, le RAG hallucine, et personne ne peut vous dire pourquoi le modèle répond ça. Nous vendons la même opération — plonger un concept dans un espace de Hilbert — mais déterministe : même entrée, même ψ, toujours. Et quand la machine ne sait pas, elle se tait. Structurellement. »

### Les questions à poser
- « Combien de vos incidents viennent d'une réponse fabriquée ? »
- « Votre audit technique peut-il rejouer un embedding ? »

### La démo (5 min)
1. `encode("lumiere")` → norme 1,0 — « la même onde, sur n'importe quelle machine » ;
2. `bind("alpha","beta")` + `unbind` → récupération 0,733 — « lier/délier, réversible, vérifié » ;
3. `memory/store` 3 faits + `memory/query` → « l'hologramme : rien n'est écrasé, l'ajout coûte O(1) » ;
4. `solve("12 * 7")` → 84 — « l'arithmétique émerge, rien n'est mémorisé » ;
5. Le refus : une requête hors vocabulaire → la machine répond par le silence.

### L'objection classique
> « Mais les LLM font tout ça mieux. »
> — « Les LLM sont statistiques : le même prompt peut donner deux réponses. Notre contrat est inverse : reproductibilité totale, traçabilité, refus calibré. Nous ne remplaçons pas votre LLM — nous remplaçons la couche où le hasard n'est pas acceptable. »
